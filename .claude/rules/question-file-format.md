# 试题文件与去重格式（Question）

定义试题 Markdown 文件的存储结构、YAML 前置元数据与 SHA-256 去重规则，供 `/question` 命令及其题型 skill 生成时统一遵守。

## 存储路径

- 试题文件：`questions/<课程名称>/<领域>/<知识点>/<题型>-<时间>.md`
- 文件名中的时间为 `yyyyMMdd-HHmmss`（24 小时制，本地时间），如 `单选题-20260816-103000.md`
- 试题图片存放在与 md 文件同级的 `images/` 目录，md 内统一用 `images/xxx.xxx` 相对引用
- 图片格式优先级：svg > png > 其他

## 文件结构

带 YAML 前置元数据的 Markdown 文件；正文各部分之间用 `---` 分割。

```markdown
---
课程名称: 智能软件工程
领域: 软件需求
知识点: 需求获取
题型: 单选题
难度: 2
hash: 3f2a9b1c7d4e4f5a9b6c2e8d1a0b3c4f5e6d7c8b9a0f1e2d3c4b5a6f7e8d9a0b
创建时间: 2026-08-16 10:30:00
---

软件需求获取阶段主要使用哪种手段与用户沟通？

---

A. 代码走查
B. 面谈
C. 编译
D. 部署

---

答案：B

---

解析：需求获取的核心手段是与用户面谈……
```

## YAML 字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `课程名称` | string | 是 | 与 courses.json 中的「名称」一致 |
| `领域` | string | 是 | 一级知识领域（来自 `<课程名>-KA.json`） |
| `知识点` | string | 是 | 二级知识点（来自 `<课程名>-KA.json`） |
| `题型` | string | 是 | 单选题 / 多选题 / 判断题 / 填空题 / 概念题 / 简答题 / 设计题 / 应用题 / 综合题 |
| `难度` | number | 否 | 1–5，默认 3 |
| `hash` | string | 是 | 题目内容的 SHA-256 哈希 |
| `创建时间` | string | 是 | `yyyy-MM-dd hh:mm:ss` 格式（本地时间） |

## 正文部分

- 每道试题**不要编号**，题干部分不用任何引导
- 各部分之间用 `---` 分割，方便后期排版与生成试卷
- 部分依题型而定（见 `.claude/rules/question-type-format.md`）：
  - 客观题（单选/多选）：题干 → 选项 → 答案 → 解析
  - 判断题：题干 → 答案 → 解析
  - 主观题（填空/简答/概念/设计/应用/综合）：题干 → 答案 → 解析（可选）
  - 主观题（简答/概念/设计/应用/综合）在答案之后附「评分标准」（答案通常分多条要点）：题干 → 答案 → 评分标准 → 解析（可选）

## 去重规则

- `hash` = 对题目内容（题干、选项与答案部分的规范化文本，去除所有空白字符后连接）计算 SHA-256；解析与评分标准不参与哈希
- 同一课程内 `hash` 相同视为重复题目：生成时跳过，校验时删除或合并
- 题目内容变更后需重新计算 `hash`
- 哈希计算：`.harness/tools/question-hash.mjs`（node 内置 crypto）

## 约束

- 「领域」「知识点」取值必须与 `<课程名>-KA.json` 中的名称一致
- 「课程名称」与 courses.json 中的「名称」一致（中文原名）
- 题目语言为中文，贴合课程名称、课程描述与知识体系
