# /question 题库建设

根据指定课程建设中文题库，覆盖其知识体系下的知识点、题型与难度，为课程教学与考核提供数据支撑。

## 参数

| 参数 | 必填 | 说明 |
|------|------|------|
| 课程名称 | 是 | 与 `courses.json` 中的「名称」一致 |
| 领域/知识点 | 否 | 限定出题范围，如「软件需求」或「需求获取」 |
| `-n 数量` | 否 | 本轮生成试题总数，默认 10；由分配算法分配到知识点、题型与难度 |
| `-t 题型` | 否 | 指定题型（9 种之一），不指定则由分配算法覆盖 |
| `-d 难度` | 否 | 难度 1–5，不指定则由分配算法覆盖 |
| `-m 比例` | 否 | 富媒体试题占比（0–100，默认 30），如 `-m 0` 关闭富媒体、`-m 100` 全部富媒体 |
| `-autoN` | 否 | 自动重复建设 N 轮，逐轮丰富题库 |

## 数据文件

- 课程数据：`.harness/data/courses.json`（只读，作为输入）
- 知识体系：`.harness/data/<课程名>-KA.json`（只读，作为输入，需先由 /knowledge 生成）
- 试题文件：`questions/<课程名>/<领域>/<知识点>/<题型>-<时间>.md`（读写，作为输出）
- 试题图片：与试题 md 文件同级的 `images/` 目录，md 内以 `images/xxx.xxx` 引用

## 文件与去重规则

试题文件格式（YAML 前置元数据 + `---` 分隔的各部分）与 SHA-256 去重规则见 `.claude/rules/question-file-format.md`。

## 题型 skill

生成某类试题时，调用对应题型 skill 并严格遵循其排版：

| 题型 | skill |
|------|-------|
| 单选题 | `/question-choice` |
| 多选题 | `/question-multiple` |
| 判断题 | `/question-judge` |
| 填空题 | `/question-fill` |
| 概念题 | `/question-concept` |
| 简答题 | `/question-short` |
| 设计题 | `/question-design` |
| 应用题 | `/question-apply` |
| 综合题 | `/question-synthesis` |

各题型排版规范统一见 `.claude/rules/question-type-format.md`。

## 工作流程

### 1. 解析参数

从用户输入提取：课程名称（必填）、领域/知识点（可选）、`-n` 数量（默认 10）、`-t` 题型、`-d` 难度、`-m` 富媒体比例（默认 30）、`-autoN`。

### 2. 查找课程

读取 `.harness/data/courses.json`，按「名称」精确匹配课程。
- 未找到 → 提示「课程不存在，请先用 /courses 创建」，结束

### 3. 读取知识体系

读取 `.harness/data/<课程名>-KA.json`。
- 不存在 → 提示「知识体系不存在，请先用 /knowledge 生成」，结束
- 存在 → 得到「领域」「知识点」全集，作为出题依据

### 4. 分配出题计划（覆盖算法）

按指定出题数量 `-n`，把题型、难度分配覆盖到知识点，目标是覆盖知识点、题型和难度：

1. **知识点集合**：未指定范围 → 全部知识点；已指定领域/知识点 → 仅该子集
2. **题型池 / 难度池**：`-t` 指定 → 仅该题型；否则 9 种题型全开。`-d` 指定 → 仅该难度；否则 1–5 全开
3. **扫描现状**：统计 `questions/<课程名>/<领域>/<知识点>/` 现有试题，记录每个「知识点 × 题型 × 难度」组合是否已覆盖
4. **按覆盖缺口取名额**（共 `-n` 个，按优先级从高到低）：
   - P1：知识点完全未覆盖（该知识点现有 0 题）
   - P2：知识点已覆盖，但该题型未覆盖
   - P3：知识点、题型已覆盖，但该难度未覆盖
   - P4：组合已全覆盖 → 轮换取当前题量最少的组合，保持题型与难度多样性
   - 每个（知识点 × 题型 × 难度）组合每轮至多取 1 个名额，保证覆盖广度
5. **富媒体挑选**：按 `-m` 比例从名额中挑选富媒体题，优先选适合图形化表达的题型（设计题 > 综合题 > 应用题 > 概念题），并优先挑选结构图/流程图/标注图类知识点
6. **产出任务单**：`[(知识点, 题型, 难度, 是否富媒体)]`，作为并行生成的任务列表

### 5. 并行生成

构建并行 Agent 系统：
- 将任务按知识点（或知识点×题型批次）分发给多个 Agent 并行生成
- 每个 Agent 调用对应题型 skill，按题型排版与富媒体规则生成试题，直接写入 `questions/<课程名>/<领域>/<知识点>/<题型>-<时间>.md`
- 富媒体题（含 `-m` 比例指定的名额）需要图片/图形/表格/公式时立即生成（图片优先 svg，其次 png），图片存入同级 `images/`，md 内以 `images/xxx.xxx` 引用，不留占位符
- 设计题/综合题按要求生成结构图 svg

### 6. 汇总与去重

- 汇总本轮生成的文件，用 `.harness/tools/question-hash.mjs`（或等价方式）计算每题 SHA-256 内容哈希，写入 YAML `hash` 字段
- 同一课程内 hash 相同视为重复：保留先到者，删除或跳过重复文件
- 存在语义近似（题干相同、答案不同等）时按重复处理并修正

### 7. 校验

生成后逐一验证：
- 重复性：hash 去重结果正确，无重复试题
- 质量：题目贴合知识点，答案正确、难度合理，干扰项有效
- 富媒体：按 `-m` 比例抽查，图片文件存在、引用路径正确（`images/xxx.xxx`），格式为 svg/png 优先
- 排版：每道试题无编号、题干无引导，各部分以 `---` 分割，符合对应题型格式（含概念/设计/应用/综合题）
- 评分标准：主观题（简答/概念/设计/应用/综合）答案分多条要点/多步骤时，含「评分标准」独立部分（满分、各要点分值、给分/扣分要求）

校验不通过的题目修正后重新保存。

### 8. 循环（auto 模式）

重复 4–7 直到满足以下任一条件：
- 达到 `-autoN` 指定的最大轮数
- 连续两轮无新增有效试题

### 9. 输出

展示本轮结果：新增题数、重复题数、覆盖知识点数/总数、题型与难度分布、富媒体题数与图片数。

## 约束

- 只读写 `.harness/data/courses.json`（读）、`<课程名>-KA.json`（读）与 `questions/<课程名>/`（读写），不涉及其他文件
- 课程名称与 courses.json「名称」一致，领域/知识点与 KA.json 一致
- 时间格式统一 `yyyy-MM-dd hh:mm:ss`（24 小时制，本地时间）；文件名中的时间用 `yyyyMMdd-HHmmss`
- 题目为中文，贴合课程名称、课程描述与知识体系，避免无关题目
- 每道试题不要编号，题干不用任何引导，各部分之间用 `---` 分割
- 富媒体按需自动生成，不引用外部图片，不使用占位符
- 出题计划分配策略见 `.claude/memory/question-allocation-strategy.md`
