版本控制系统可分为集中式与分布式两大类。请简述集中式与分布式版本控制的主要区别，并说明在 AI 项目（如大模型训练）中通常采用哪种方式及原因。

---

答案：参考要点：
1. 集中式（如 SVN、CVS）：版本历史集中存放于中央服务器，开发者需从中央仓库检出工作副本、联网提交，无法离线提交或查看完整历史，服务器故障会中断协作。
2. 分布式（如 Git）：每个开发者本地都拥有一份完整仓库（含全部历史），提交先在本地完成，再推送到远程；支持离线工作、本地分支与灵活协作，权限与评审通过远程仓库控制。
3. AI 项目采用方式：通常以 Git 为主的分布式版本控制管理训练代码、数据处理脚本与配置，支持团队成员多地并行开发、实验分支隔离与本地快速迭代。
4. 大对象处理：模型权重、大数据集体积巨大，不直接入库，借助 Git LFS 或 DVC 等工具以内容寻址方式外置存储，并与代码版本绑定，实现端到端可复现。

---

评分标准：（满分 10 分）
- 要点 1（2 分）：答出集中式特点（版本历史集中存放中央服务器、需联网检出提交、无法离线提交或查看完整历史、服务器故障中断协作）即给分。
- 要点 2（2 分）：答出分布式特点（本地持有完整仓库含全部历史、先本地提交再推送远程、支持离线工作/本地分支/灵活协作）即给分。
- 要点 3（3 分）：答出 AI 项目采用方式（通常以 Git 为主的分布式版本控制管理训练代码、数据处理脚本与配置，支持多地并行开发、实验分支隔离与本地快速迭代）即给分。
- 要点 4（3 分）：答出大对象处理（模型权重、大数据集借助 Git LFS 或 DVC 以内容寻址方式外置存储、并与代码版本绑定实现端到端可复现）即给分。
- 缺要点或表述不清者，视情况酌情扣分。

---

解析：分布式版本控制因离线可用、本地持有完整历史与协作灵活，成为现代开源与团队协作的主流；AI 项目同样以 Git 分布式仓库为主，再配合数据/模型版本管理工具解决大对象版本问题，二者组合才能覆盖代码、数据、模型三类资产的版本管理需求。
